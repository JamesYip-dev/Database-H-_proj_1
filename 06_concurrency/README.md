# 并发查询与持久化递增

目的：在相同正确性和保存要求下比较混合吞吐量，以及单次保存成本，检验简单 CSV 快照方案的写入扩展性；同时比较 PG/OG 随并发级别变化的表现。

运行 `./06_concurrency/run-concurrency.sh`。输入电影编号来自 movies.csv，按输入数量建计数副本，不硬编码行数。每方法每批均从零开始。

- 每批 2,000 个固定操作：80% 读取、20% views+1，热点为前 min(64,电影数) 个编号。种子 20261011；所有实现及并发级别使用同一任务列表。
- 1、4、8 个工作线程，三组；预热 200 个操作后重新装入初始数据。轮换并发级别与方法顺序，不同时测两种实现。
- DB 每线程独立连接及 PreparedStatement，READ COMMITTED、自动提交；读 SELECT、写单条 UPDATE views=views+1。每批 TRUNCATE、重新插入全部初始行并 ANALYZE，避免恢复过程累积历史版本。恢复、连接准备及校验不计时。
- CSV 预加载不可变计数快照和编号索引。读者无锁读取当前已保存快照；写者持锁复制、递增、重写整个文件，force(true)、原子替换并刷目录后才公布新版本。写入计时包含等待。没有故意实现可丢失更新的文件方案。
- 工作线程准备完成后同时开始，总耗时计至全部操作完成。每个操作另存延迟；混合吞吐量为 2000/批次秒数，不是单次耗时中位数的倒数。
- 每批从实际 CSV/数据库复读全部计数，逐编号核对预期递增；核对全部操作仅执行一次、读取在合法范围内及同一线程同编号不回退。所有检查在计时外。

summary.csv 保存三组批次吞吐量、读写中位数及校验状态；group-*.csv 保存逐操作结果与计时。报告按三组吞吐量中位数比较，不把快速读取和持久化写入混成一个中位数。

范围：一个 Java 进程内的多个线程，数据库有相应多个连接。不验证多个 CSV 写入进程、断电或崩溃恢复。文件可以改为分片、日志或其他结构，但那需要另行设计与比较，不等于文件管理绝不可能达到数据库性能。
