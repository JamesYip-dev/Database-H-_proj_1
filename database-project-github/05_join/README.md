# 四表关联统计

目的：比较完整文件查询成本、预建索引后的 Java 计算成本及两库 SQL 执行，观察执行计划选择；不预设数据库更快。

运行 `./05_join/run-join.sh`。prepare-data.py 从原始 filmdb.sql 提取 countries、movies、people、credits 的必要字段，记录来源 SHA-256 和各表数量，检查所有引用及参演主键。数据行数由输入读取。

查询：按洲及年代统计演员的电影数，返回前 20 人。credited_as='A'，主键确保同一演员在同一电影中只计一次；数量降序、peopleid 升序处理并列。任务为欧洲/亚洲 1980–1999、美洲 2000–2019、全部地区 1960–1979。

Java 用人物编号、国家编号与电影编号索引，以及电影到演员列表的索引，先筛电影再计数排序。CSV 路线每次读取并建立索引；Java memory 的加载和索引建立在计时外，但查询结果每次重新计算，不缓存聚合结果。

两库使用相同字段、主键与外键，credits 主键顺序为 movieid、peopleid、credited_as。导入、逐表核对及 ANALYZE 不计时，不强制执行计划。独立实验表结束后删除，原始 public 业务表不变。

每任务三组，每组预热 10 次、正式 30 次；固定种子轮换任务顺序和方法执行顺序，不清缓存。每次核对完整前 20 名及排列。报告以三组合并 90 次的中位数呈现；各组保留在 results。postgres-plans.txt、opengauss-plans.txt 是计时后的诊断计划，不与客户端耗时直接相减。
